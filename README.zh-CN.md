# gil-inspect

[English](README.md) ｜ **中文**

> 🤖 **AI 助手：请先读 [`AGENTS.md`](AGENTS.md)** —— 它把这个仓库地址直接映射成
> 「用哪个命令、产出哪些文件、怎么解读、以及有哪些**做不到**」。

用于读取《原神》UGC 编辑器（千星沙箱 / Miliastra Wonderland）**官方「导出存档」功能**产出的关卡存档
（`.gil`）的**只读**检查工具。

它回答的是关于**你自己那份导出**的问题：文件里到底有哪些元件、自定义变量和节点图；相比上次导出
改了什么；以及 —— 配合一张映射表 —— 图里每个节点叫什么名字。

```
gil-inspect -path export/MyLevel.gil -graphs
```

> **文档双语维护。** 本文件与 [`README.md`](README.md) 需**一起改**：改了一个，就在同一次提交里更新另一个。

## 当前能力

| 能力 | 状态 |
| --- | --- |
| 容器头、顶层字段表、压缩检测 | ✅ 可用 |
| 与上次快照做差异对比（字段尺寸、新增/消失的名称） | ✅ 可用 |
| 关键词命中清单（你关心的标识符在不在、出现几次） | ✅ 可用 |
| 中文串 / ASCII 标识符提取 | ✅ 可用 |
| **节点图**：图名、节点列表、**节点类型 id**、坐标、自定义标题、引用的变量名 | ✅ **两种容器都支持** —— 关卡存档（`.gil`，字段 `f10`）与**资产文件**（`.gia`，每个复合节点各自的图） |
| 节点类型**名称** | ✅ 已映射 **36 个** id：**9 个**经真实节点图核对后**内置**，另有 **27 个**在随仓库提供的 `node-types.txt` 里；每个名字都在官方节点目录核对过。我们自己的关卡报告 **0 个未映射类型** |
| 图**连线**（哪个引脚接到哪个） | ⚠️ **实验性，尚不可信** —— 见下 |

### 连线这一块明确不承诺

第一版解码会在中间文件里输出 `links:`，但拿一张**接线已知**的图（截图）做基准比对时，它只还原出
**14 条真实连线里的 2 条**，还凭空多出一些。原因是：目前解出的引脚块里**根本没有真实存在的节点对**。
因此该段在输出里被标为 `EXPERIMENTAL`；将来解码器必须命中的**真值**记录在
[docs/node-graph-extraction.md](docs/node-graph-extraction.md)。

## 用法

```
gil-inspect -path <存档.gil> [参数]

  -graphs          输出 <名字>.graphs.md —— 纯文本中间文件
  -lint            输出 <名字>.lint.md —— 常规检查（见下）
  -scan 目录       批量扫描目录下的关卡存档（.gil）与资产文件（.gia）：汇总表 + 类型 id 并集
  -nodetypes FILE  节点类型映射表（默认 node-types.txt）
  -graphfield N    存放节点图的容器字段号（默认 10）
  -graphdump       输出 <名字>.graph-fN.md —— 完整缩进树（解码用辅助）
  -pins            输出 <名字>.pins.md —— 原始引脚描述（标定用辅助）
  -keys a,b,c      关键词清单（ASCII）；额外的关键词可放在 JSON 数组文件里
  -keyfile FILE    默认 gil-keys.json
  -out FILE        报告路径（默认 <名字>.inspect.md）
  -snapshot FILE   默认 <目录>/gil-snapshot.json
```

典型用法：

```
gil-inspect -path export/Level.gil                    # 盘点 + 与上次导出对比
gil-inspect -path export/Level.gil -graphs            # 生成可读的节点图中间文件
```

中间文件刻意做成**纯 markdown**（不用 JSON），并且丢掉了坐标、无关的节点编号等一切会干扰
人或 AI 阅读的东西：

```
## 关卡-建筑销毁

nodes:
  1	终止定时器	"测试出兵定时器"
  2	查询自定义变量快照	"isBase"
  3	实体销毁时
  4	双分支
  10	多分支	"4"	refs: 5
links:
  # EXPERIMENTAL - not verified, do not trust yet
```

## 常规检查（`-lint`）

> 🚫 **本工具不替代编辑器自带的检查。** 官方有两道：
> **试玩校验**（阻断性错误，会阻止试玩）与 **风险检查**（非阻断提示，多是数据上的错误、
> 或违背隐藏规则）。**官方能查出来的一律以官方为准**；`-lint` 刻意只补它们**看不到**的那些：
> 命名约定、**分别配置的多处之间的一致性**、以及**文件本身**的状态。
> 若发现某项与官方重复，应当**删掉它**，而不是两头维护。
>
> ✅ **已实测确认的盲区（2026-10-05）**：自定义变量**类型写错**（例如把「元件ID」存进整数变量）
> **风险检查不会报** —— 机制只是**静默不生效**。下面那几条类型检查就是为这个盲区存在的。

不需要你额外提供信息就能跑的静态检查：

| 检查项 | 找什么 |
| --- | --- |
| `dangling-reference` | 某个标识符**只在节点图区出现过** —— 若它是变量名，说明没有任何组件声明它（即「图里用了、但元件/关卡上没配」这种情况） |
| `reference-typed-as-number` | 变量名读起来像**引用**（`*_unit` / `*_id` / 元件 / 模板），却声明成了**数值类型** —— 这就是「元件ID 存进整数变量、机制静默不生效」那个坑 |
| `variable-type-conflict` | **同一个变量名在不同位置被声明成了不同类型** |
| `default-value-type-mismatch` | 声明的类型与所带默认值的编码不一致 |
| `unmapped-variable-type` | 类型 id 还没有名字（填到 `var-types.txt` 即可；本身无害） |
| `graph-only-name` | 只出现在图区的中文名：是变量就值得怀疑，是复合节点 / 节点自定义标题 / 定时器名则正常 |
| `similar-names` | 一个名字是另一个的前缀（易混，如 `选阵营` 与 `选完阵营`） |
| `naming-style-mix` | snake_case 与 camelCase 混用 |
| `banned-name` | 读起来像「我方 / 敌方」的命名 —— 本架构是对称双阵营 |
| `graph-large` / `empty-graph` | 每张图的节点数（对照平台上限） |
| `parse-health` | 顶层字段走查在文件结束前很远就停了 |

两点务必记住：

- 每条都是**待核对项，不是判定** —— `.gil` 里没有足够上下文来确证（只在图区出现的标识符，完全可能是图名或定时器名）；
- **从不自动修复**，也没有「一键应用建议」模式 —— 本工具始终只读。

报告开头会列出**已识别的图名**，因为这些名字本来就只出现在图区，否则会被误当问题。

报告末尾还会给出**全部已声明自定义变量的清单** —— 变量名、声明类型、声明处数量、以及存下来的默认值：

```
| 变量 | 类型 | 声明处 | 默认值 |
| spawn_interval | 浮点 | 12 | 12 |
| spawn_unit | 元件ID | 12 | — |
| isBase | 布尔 | 4 | — |
```

类型 id 是内部的。其中三个已用**我们建房时已知类型**的变量实测确认 ——
**4 = 布尔、10 = 浮点、21 = 元件ID** —— 其余显示为 `type N（未映射）`，
填进 `var-types.txt` 即可命名（格式与 `node-types.txt` 相同，仓库不内置第三方表）。

## 节点类型名：`node-types.txt`

节点类型在文件里存的是**内部 id**（`3360`、`82` …），**名称不存在文件里**，所以工具读取一张你自己
提供的映射表 —— 每行 `id<TAB>名称`，`#` 开头是注释：

```
3360	查询自定义变量快照
373	实体销毁时
```

这张表**刻意不内置在仓库里**：来源由你决定，本仓库不转发任何第三方数据。
每次生成的 `.graphs.md` 末尾都会列出**仍未映射的 id 及其使用次数**，方便分批补齐。

未映射的 id 会显示成 `?3360`，而不是被隐藏。

## 合规边界（请务必守住）

本游戏的创作者守则禁止「**制作、发布**、传播、使用、宣扬、教唆外挂、私服等妨碍游戏公平性的
模拟用户操作、改变操作环境、**修改数据**的任何辅助工具或程序**」。因此本工具：

- **从不写入、改写或修补 `.gil`** —— 输入文件只以只读方式打开；
- **从不接触游戏的安装目录、缓存或运行时**；
- **从不自动化操作编辑器**（不模拟输入、不做 OCR、不注入）；
- 只写出报告：一份 Markdown 报告、一份 Markdown 节点图文件，以及一份记录了字段尺寸与标识符
  **名称**的 JSON 快照（绝不包含载荷字节）。

> ⚠️ **请勿把它改造成"写入器"。** 一个能**修改**关卡数据的工具就越过了上面那条线 ——
> 而**发布**这样的工具，本身就是被禁止的行为。
